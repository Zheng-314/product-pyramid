# Layer 4: UI/UX 设计原则

## 4.1 设计原则

### 通用原则（适用于所有产品形态）

1. **Less is More**：简洁设计，用户浏览时是扫描而不是仔细观看
2. **遵循用户习惯**：不要随意创新，利用用户熟悉的组件、图标和设计规范，不要增加学习成本——除非创新带来的体验能覆盖改变带来的学习成本
3. **设计传达产品理念**：视觉语言应该和产品定位一致
4. **降低学习成本**：设置引导流程等方式帮助用户上手
5. **重点突出**：通过颜色、大小、布局凸显核心信息

### 体验即武器

产品的体验是留住用户的一大武器。有时候不需要加太多功能，而是思考如何用更少的按钮和功能让用户在产品里达到自己的目标。

### 不同产品形态的差异

| 形态 | 设计重点 |
|------|---------|
| **硬件产品** | 工业设计、交互反馈、耐用性 |
| **Web 端** | 信息架构、响应式布局、键盘/鼠标交互 |
| **移动端** | 单手操作、触控友好、碎片化使用 |
| **AI 原生产品** | 对话式交互、期望管理、不确定性处理 |

## 4.2 信息架构

### 核心问题

1. 用户进来第一眼看到什么？
2. 核心操作需要几步完成？
3. 信息的层级关系是什么？哪些是主信息，哪些是辅助信息？

### 设计方法

1. **画出用户核心路径**：从进入产品到完成目标的最短路径
2. **确定页面层级**：首页 → 核心功能页 → 详情页
3. **每个页面只做一件事**：如果一个页面承载了太多功能，拆分它
4. **导航要清晰**：用户随时知道自己在哪，能去哪

## 4.3 交互设计

### 核心原则

1. **反馈及时**：每个操作都应该有明确的反馈（加载、成功、失败）
2. **可撤销**：用户犯错后能轻松回退
3. **一致性**：相同的操作在不同地方应该有相同的交互方式
4. **渐进式披露**：不要一次性展示所有信息，按需展示

### AI 产品的特殊考虑

1. **期望管理**：用户对 AI 的期望往往过高或过低，需要明确告知能力边界
2. **不确定性处理**：AI 的输出可能不完美，需要提供修正和反馈的入口
3. **等待体验**：AI 处理需要时间，等待时要有明确的进度提示和预期时间
4. **人机协作**：不是让 AI 替代用户，而是让 AI 增强用户的能力

## 4.4 原型设计

### 快速原型工作流

1. **从0到1**：快速出原型进行验证，不需要完美
2. **从1到N**：思考新功能带来的学习成本是否能被体验效益覆盖

### 原型检查清单

- [ ] 核心页面的信息架构是否清晰？
- [ ] 用户核心路径的交互流程是否顺畅？
- [ ] 关键操作是否在 3 步以内完成？
- [ ] 是否有明确的反馈机制？
- [ ] 是否降低了用户的学习成本？

## 引导问题

1. 你的产品是什么形态？（硬件/Web/移动端/AI原生）
2. 用户进入产品后，第一眼应该看到什么？
3. 核心操作需要几步完成？能不能再少一步？
4. 你的设计如何传达产品的核心理念？
5. 如果用户第一次使用，他能在 30 秒内理解产品是做什么的吗？
